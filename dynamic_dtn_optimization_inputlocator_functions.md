# Dynamic DTN Optimization InputLocator Functions

## Issue Description

The `dynamic_dtn_optimization_part2.py` script was designed to rerun the GA optimization using the thermal network results generated by `dynamic_dtn_optimization.py`. However, it was not correctly accessing these results, leading to errors when running the script.

The issue was that `dynamic_dtn_optimization.py` generates thermal network results and copies them to a subfolder of the dynamic DTN optimization folder, but `dynamic_dtn_optimization_part2.py` was trying to access the original thermal network results instead.

## Solution

The solution was to:

1. Add new functions to `inputlocator.py` to point to the thermal network results generated by `dynamic_dtn_optimization.py`
2. Modify the `_load_cost_data` method in `dynamic_dtn_optimization_part2.py` to use these new functions

### New Functions Added to InputLocator

The following functions were added to `inputlocator.py` to point to the thermal network results generated by `dynamic_dtn_optimization.py`:

1. `get_dynamic_dtn_network_layout_costs_file`
2. `get_dynamic_dtn_thermal_network_layout_massflow_edges_file`
3. `get_dynamic_dtn_thermal_network_layout_massflow_nodes_file`
4. `get_dynamic_dtn_thermal_network_velocity_edges_file`
5. `get_dynamic_dtn_network_pressure_at_nodes`
6. `get_dynamic_dtn_network_total_pressure_drop_file`
7. `get_dynamic_dtn_network_energy_pumping_requirements_file`
8. `get_dynamic_dtn_thermal_network_substation_ploss_file`
9. `get_dynamic_dtn_network_linear_pressure_drop_edges`
10. `get_dynamic_dtn_network_total_thermal_loss_file`
11. `get_dynamic_dtn_network_thermal_loss_edges_file`
12. `get_dynamic_dtn_network_linear_thermal_loss_edges_file`
13. `get_dynamic_dtn_thermal_network_pressure_losses_edges_file`
14. `get_dynamic_dtn_thermal_network_plant_heat_requirement_file`
15. `get_dynamic_dtn_network_temperature_supply_nodes_file`
16. `get_dynamic_dtn_network_temperature_return_nodes_file`
17. `get_dynamic_dtn_network_temperature_plant`

These functions follow the same pattern as the existing thermal network functions, but they point to the dynamic DTN optimization thermal network folder instead of the regular thermal network folder.

### Modified _load_cost_data Method

The `_load_cost_data` method in `dynamic_dtn_optimization_part2.py` was modified to use the new `get_dynamic_dtn_network_layout_costs_file` function instead of loading from the database. The key changes were:

1. Changed the method to load cost data from the dynamic DTN thermal network costs results using `self.locator.get_dynamic_dtn_network_layout_costs_file(self.network_type)` instead of loading from the database.
2. Added a fallback mechanism to use the original cost file if the dynamic DTN cost file is not found.
3. Simplified the code by removing the complex logic for reading Excel files and filtering by network type, since the CSV files from the dynamic DTN optimization are already filtered.
4. Kept the logic for loading pipe cost data and pump cost data from the database, as these are still needed for detailed calculations.

## Benefits of the Changes

1. **Consistency**: The code now consistently uses the thermal network results generated by `dynamic_dtn_optimization.py` instead of the original thermal network results.
2. **Maintainability**: All file paths are managed in one place (`inputlocator.py`), making the code more maintainable.
3. **Clarity**: The code clearly shows that it's using the dynamic DTN optimization results.
4. **Fallback mechanism**: The code includes a fallback mechanism to use the original files if the dynamic DTN files don't exist.

## Testing

The changes were tested by running the `dynamic_dtn_optimization_part2.py` script and verifying that it correctly uses the thermal network results generated by `dynamic_dtn_optimization.py`.

## Conclusion

The changes made to `inputlocator.py` and `dynamic_dtn_optimization_part2.py` ensure that the script correctly uses the thermal network results generated by `dynamic_dtn_optimization.py`, making the dynamic DTN optimization process more robust and maintainable.
