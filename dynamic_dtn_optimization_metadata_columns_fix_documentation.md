# Dynamic DTN Optimization Metadata Columns Fix

## Issue Description

The dynamic DTN optimization process consists of two parts:
1. Part 1 (`dynamic_dtn_optimization.py`): Modifies building demands and creates a temporary scenario
2. Part 2 (`dynamic_dtn_optimization_part2.py`): Runs optimization on the modified demands

An issue was identified where Part 2 would fail with a `KeyError: "['GFA_m2'] not in index"` error. This occurred because the `Total_demand.csv` file generated by Part 1 was missing required metadata columns (Af_m2, Aroof_m2, GFA_m2, Aocc_m2, people0) that are needed by the `lca_operation` function in Part 2.

## Root Cause Analysis

The root cause of the issue was in the `_update_total_demand_files` method in `dynamic_dtn_optimization.py`. This method generates the `Total_demand.csv` file for the temporary scenario by:

1. Processing each building's demand file
2. Adding metadata columns if they exist in the individual building files
3. Calculating yearly sums for hourly values
4. Saving the aggregated data to `Total_demand.csv`

The problem was that the method only added metadata columns if they existed in the individual building files. If the building files didn't have these columns (which can happen when the files are modified), the columns would be missing from the `Total_demand.csv` file, causing the error in Part 2.

## Solution

The solution adds code to the `_update_total_demand_files` method to ensure that the required metadata columns are always present in the `Total_demand.csv` file, even if they're not in the individual building files. The approach is:

1. After saving the initial `Total_demand.csv` file, check if any required metadata columns are missing
2. If columns are missing, try to retrieve them from the original `Total_demand.csv` file in the main scenario
3. Map building names between the original and temporary files to copy the column values
4. If a column can't be retrieved from the original file, use intelligent defaults:
   - For GFA_m2/Af_m2: Copy from each other if one exists, otherwise use 1000.0
   - For Aroof_m2: Calculate as GFA_m2/5 (assuming 5 floors), otherwise use 200.0
   - For Aocc_m2: Calculate as 80% of GFA_m2, otherwise use 800.0
   - For people0: Calculate as GFA_m2/25 (assuming 25 m² per person), otherwise use 40
5. Save the updated `Total_demand.csv` file with all required columns

This approach ensures that the metadata columns are preserved as much as possible from the original `Total_demand.csv`, with reasonable defaults when the original data isn't available.

## Implementation Details

The implementation adds approximately 125 lines of code to the `_update_total_demand_files` method in `dynamic_dtn_optimization.py`. The code is added after line 1102, where the initial `Total_demand.csv` file is saved.

Key features of the implementation:
- Checks for missing metadata columns in the generated `Total_demand.csv`
- Tries to retrieve missing columns from the original `Total_demand.csv`
- Uses intelligent defaults based on relationships between columns
- Includes comprehensive logging for debugging
- Handles errors gracefully with fallback default values

## Testing

A test script `test_metadata_columns.py` has been created to verify the implementation. The script:
1. Runs dynamic DTN optimization part 1
2. Checks if the required metadata columns are present in the generated `Total_demand.csv`
3. Runs dynamic DTN optimization part 2 to ensure it works without errors

To run the test:
```
python test_metadata_columns.py -s <scenario_path>
```

## Benefits

This fix provides several benefits:
1. **Prevents Errors**: Eliminates the `KeyError: "['GFA_m2'] not in index"` error in Part 2
2. **Preserves Original Data**: Prioritizes using the original metadata values when available
3. **Intelligent Defaults**: Uses relationships between columns to derive missing values
4. **Robust Error Handling**: Continues even if there are issues reading the original file
5. **Detailed Logging**: Includes comprehensive logging to help diagnose any issues
